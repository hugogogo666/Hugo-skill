# 亚马逊广告方案 Skill

## 目标

基于商品事实、市场流量和卖家经营数据，生成能直接搭建、监测和迭代的 Amazon 广告方案。区分数据事实、业务判断、执行建议和数据缺口；不保证排名、销量或利润结果。

## 工作流

### 1. 确认口径

- 确认 ASIN、站点、是否为自有商品、广告目标和计划周期。
- 默认美国站；只给 ASIN 且要求广告方案时，可按自有 ASIN 处理并声明假设。
- 记录数据快照日期。价格、排名、流量、竞价和促销均按时点数据处理。
- 精算预算时优先获取成交价、采购及头程成本、FBA/平台费用、广告前利润、库存、目标 ACoS 和后台 CVR。缺失时使用 25%/30%/35% ACoS 情景，不伪造精确值。

### 2. 获取数据

优先调用当前环境的数据接口，接口不足后再做网页或浏览器补充。

- Amazon 单品详情、关键词找产品：优先 Amazon 商品数据接口。
- 类目规模、趋势、价格带和品牌结构：优先类目与趋势数据接口。
- 关键词流量结构、自然排名和广告排名：优先关键词流量数据接口。
- 历史价格、Buy Box、BSR：使用历史价格数据源补充。
- 后台真实表现：优先用户提供的广告报告、业务报告、搜索词报告和搜索查询表现报告。
- 评论痛点：使用评论/VOC 数据，或在必要时抽样分析。

直接工具未暴露时，先通过 MCP Broker 发现服务、确认参数并调用。只有目标服务不存在或调用明确失败后才降级。不得要求用户自行配置数据供应商 Token 作为第一步。

用户可见内容只呈现数据、事实、结论和日期，不披露受保护的供应商、内部工具名、参数、日志或调试链路。服务不可用时使用“服务暂不可用”“当前数据暂不可获取”等中性表述。

### 3. 判断 ASIN 阶段

选择一个主阶段并说明证据：

- 冷启动：无评论、无流量词、无自然位置。
- 测试期：少量评论或关键词，订单不稳定。
- 成长期：已有自然词、评论和类目排名，但流量集中或广告依赖高。
- 稳定期：核心自然排名和转化稳定，重点转向利润与扩量。
- 重建期：旧活动混乱、浪费明显，或自然排名不随广告改善。

已有基础的 ASIN 不要机械称为“从零开始”，改为“从当前基线重建广告底盘”。

### 4. 建立关键词分层

从产品本体、属性、规格、材质、功能、人群、场景、痛点、利益、兼容性、替代品和竞品中提取词根：

- S：战略核心词，高相关且有排名价值。
- A：核心增长词或高意图属性词。
- B：场景、规格和长尾效率词。
- C：探索词、品牌词、弱相关场景词。
- D：结构不匹配、风险承诺或明显无关词，进入否定库。

综合商品相关性、购买意图、Listing 承接、搜索需求、竞争成本和利润空间。不得把高搜索量直接等同于值得高价投放。

### 5. 计算经济模型

```text
盈亏平衡 ACoS = 广告前单件贡献利润 ÷ 实际成交价
目标 CPA = 实际成交价 × 目标 ACoS
最高可承受 CPC = 实际成交价 × 目标 ACoS × 广告 CVR
理论无单点击阈值 = 目标 CPA ÷ 实际 CPC
```

市场建议竞价只作为竞争参考，不能替代可承受 CPC。成本或 CVR 未知时输出区间和验证动作。

### 6. 设计广告架构

按预算和阶段组合，不机械开满：

1. SP 精准—战略核心词。
2. SP 精准—属性/长尾盈利词。
3. SP 精准—人群或场景词。
4. SP 词组—词根扩展。
5. SP 广泛—低价探索。
6. SP 自动—紧密、宽泛、替代商品分开管理。
7. SP 商品定向—直接竞品、高价竞品、弱评分竞品、自有防守。
8. 品牌词、竞品品牌词独立隔离。
9. 品牌资格和转化词成熟后再评估 SB/SBV。

探索活动默认使用动态竞价“仅降低”；验证转化后的精准词才测试更积极的竞价和首页首位加价。

预算参考：低于 $30/天保留核心精准、属性/场景精准、自动紧密和商品定向；$50–$70/天使用完整 SP 结构；$100+/天仅在转化、库存、利润和自然排名反馈成立时放大。

### 7. 输出路线图与优化规则

至少给出第 0–3、1–7、8–14、15–30、31–45 天；需要长期规划时扩展到 46–90 天。每阶段包含目标、动作、产出、验收标准和禁止事项。

最低优化规则：

- 有单且 ACoS 达标：加价或预算 5%–15%，3–5 天复查。
- 有单但 ACoS 略高：降价约 10%，同时检查自然排名与转化。
- 普通词花费达到 1.5 倍目标 CPA 无单：降价 15%–20%。
- 普通词花费达到 2 倍目标 CPA 无单：暂停或否定。
- 战略核心词达到 2 倍目标 CPA 无单：先检查 Listing、价格和自然排名，不机械否定。
- 曝光高、CTR 低：检查搜索意图、主图、标题、价格和 Coupon。
- CTR 好、CVR 低：检查 Listing 承接、Offer 和错词。
- 预算提前耗尽且 ACoS 达标：预算增加约 20%。
- 搜索词转精准后，先确认新活动能接住流量，再在来源活动做否定精准。

详细方法读取 `references/methodology.md`。

## 标准交付结构

1. ASIN 当前诊断与阶段判断。
2. 核心问题与 Listing 承接清单。
3. 关键词 S/A/B/C/D 分层与初始竞价。
4. 广告活动架构、命名、预算占比和管理规则。
5. 盈亏模型与预算情景。
6. 否定词、隔离词和商品定向候选。
7. 45/90 天推进路线图。
8. 优化、止损和复查规则。
9. KPI、监测模板和待补数据。

所有 ASIN 在用户可见报告中使用对应 Amazon 商品链接。

## Excel 交付

用户要求 Excel、表格、执行表或下载文件时：

1. 将分析整理成符合 `references/input-schema.md` 的 UTF-8 JSON。
2. 运行：

```bash
python3 scripts/build_ad_plan_excel.py --input <analysis.json> --output <absolute-output.xlsx>
```

3. 重新打开工作簿，验证 10 个工作表、可编辑公式、下拉项和文件可读性。
4. 返回完整绝对路径，并用单反引号包裹。

默认工作表：ASIN现状诊断、关键词分层与竞价、广告活动架构、预算与盈亏模型、阶段推进计划、优化与止损规则、否定词与隔离词、Listing承接清单、广告监测模板、KPI与数据缺口。

`assets/B0F6D5RSGH_亚马逊广告方案示例.xlsx` 仅作为版式和字段示例，不得复制其中的商品结论到其他 ASIN。
